# 从任务证据到场景流程

通用机制由 Skill 提供。用户库中 `run` 保存简短任务证据，`lesson` 保存局部经验，`workflow` 保存场景流程。通过 ID 关联，旧版实现、修复、约定和决策也可以直接作为经验引用。

## 检索

先匹配目标，再核对输入、环境、约束及验收标准。按需读取最相关记录，证据不足再扩展，不加载全库。

- 条件一致且证据仍成立：采用。
- 步骤相似但输入、环境或验收不同：调整，说明差异。
- 只有主题相似：参考，不称为可直接复用。
- 无匹配：按领域方法正常执行，不捏造历史经验。

## 提炼

首次完成有重复价值的任务，可以保存 run 和候选 workflow，不要求同时建立 lesson。将本次日期、文件名、路径等变成输入参数，避免把特例固化。

流程需包含触发场景、不适用范围、输入、步骤与条件分支、输出和验收。只有以下条件同时成立才设为 active：

- 有至少一条按该流程实际执行且验收通过的 run 引用；
- 证据支持声明的范围，单一环境的成功不得泛化为所有环境；
- 依赖、分支和未验证部分明确；
- 没有尚未解决、会否定该范围的反例。

执行次数不是成熟度门槛。多次未检查的结果仍是候选；工具只检查结构条件，证据是否充分由助手判断。首次任务只能生成候选流程，不反向虚构“已经按此流程复用”。

## 修正

成功复用：追加简短证据，仅有新适配点才修改流程。

失败：区分输入问题、执行偏离、环境变化和流程缺陷，根因未确定时标明假设。确认流程有问题后缩小范围、修订或标记过期。

用户纠正：区分本次例外与原结论错误，只有后者改通用流程。明确要求保存的偏好作为有范围的 convention，不自动推断习惯。

重复记录较多时可在用户要求整理后摘要归档，不自动删除支撑有效流程的证据。

## 保存顺序

写前复读已有文件，保留人工内容。先写 run/lesson，再写引用它们的 workflow，最后更新索引。不同任务使用不同 ID；冲突时不覆盖。工具不提供多文件事务，部分写入需报告已保存与未保存内容。

## 示例：月报

第一次核对数据并生成月报后保存产物和核对结果，提炼候选流程；下一次确认口径未变，按流程执行并记录验收；季度末新增累计数据时提炼条件分支，不改成所有月报都执行。

这是虚构的机制示例，不是已经验证的流程，也不提供发送报告的授权。
