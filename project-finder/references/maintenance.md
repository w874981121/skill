# 维护与检索质量

## 控制读取量

先按业务能力与症状搜索索引，再按框架、运行环境和约束缩小范围。优先阅读最相关的少量记录；证据不足时再扩展，不一次加载整个知识库。

候选没有覆盖关键约束时，继续查代码或报告缺口，不靠标签相似就认定可复用。优先匹配项目约定；共享经验与项目约定冲突时说明差异，不能直接覆盖本项目规则。

## 写入决策

- 没有未来复用价值：跳过。
- 有价值但未经确认：记为候选，保留未确定部分。
- 与既有记录相同：更新来源及验证证据，不新建副本。
- 业务条件或实现差异显著：保留变体并说明区别。
- 明确推翻旧结论：添加新证据，标记旧记录过期或被替代，保留历史。

用户纠正记忆时，先分清是事实修正还是新任务的局部要求。局部要求不能覆盖所有项目。

## 检查工具

工具需要 Python 3.9+ 和 PyYAML。若环境缺少依赖，使用人工检查，不必为了使用 Skill 自动安装软件。

```text
python <skill目录>/scripts/memory_check.py <知识库目录>
python <skill目录>/scripts/memory_check.py <知识库目录> --index
```

默认输出 JSON 检查结果；有格式错误退出码为 1。`--index` 只在无错误时向标准输出生成 Markdown 索引，警告输出到标准错误。工具不写文件，不读来源项目，也不检索共享库。

生成索引后核对内容，再由助手写入 `index.md`；保存前保留原索引里的人工备注。检查失败应修复本次改动造成的问题；不要为了通过检查擅自重写用户已有资料。

检查范围：v1/v2 配置、必需字段、日期、路径结构、重复 ID、工作区映射、替代引用和循环；v2 还检查任务结果、流程输入/步骤/验收、关联记录，以及 active 流程的执行证据关联。证据真实性、条件是否失效、是否值得复用仍由助手核对，检查通过不代表结果已验证。

没有 Python/PyYAML 时按同样范围人工检查，并说明没有运行自动检查。
